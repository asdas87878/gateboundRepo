## 3. What worked

### Colours
**Final:** `studio_match` in `tools/art/house_looks.py`. It's `3_dark_warm_stone` (the approved design) plus a Studio-only grade. Tuples are (hue turn in degrees, sat gain, value gain, gamma on value).

| Material | Approved look (`3_dark_warm_stone`) | Studio grade on top |
|---|---|---|
| Wood | (2, 0.92, 1.05, 0.85) | (0, 1, 1.1, 0.95) |
| Green wood | (14, 1.3, 1.06, 0.95) | (-14, 0.8, 1.08, 1.0) |
| Plaster | (2, 0.82, 1.05, 0.9) | (0, 1, 1.06, 0.9), then linear tint (1.0, 0.9, 0.74), full on light paint, none on darks |
| Modelled stone | (0, 0.9, 0.68, 1.2), tint (1.02, 0.92, 0.8) | (0, 1, 1.08, 0.94), then linear tint (1.05, 1.0, 0.9) |
| Terracotta | (2, 1.22, 1.08, 0.94) | (0, 1, 1.06, 1.0) |
| Slate | (0, 1.3, 1.12, 0.92) | (0, 0.8, 1.0, 1.0) |
| Thatch | (0, 0.92, 1.0, 1.0) | none |
| Glass | `sky_soft` painted, top (122, 186, 226) to foot (70, 122, 186) | (0, 0.72, 1.12, 1.0) |

Tattered keeps its own greyed values through `OVERRIDE`: wood (0, 0.62, 0.9, 1.05), and dark dirty glass.

**Plaster accent** (`cottage_kit.py`): multiplied `ACCENT_DEEP` (0.74, 0.72, 0.86) to `ACCENT_LIGHT` (0.8, 0.88, 0.88), four stacked washes per enclosed block (`ACCENT_LAYERS`), 55% clusters, fingers at half strength elsewhere (`ACCENT_FINGER_FLOOR` 0.5), depth 0.37 of a block, `ACCENT_CORNER` 0.4.

### Sizes and spacing
- Windows: all 2.6 x 2.6 studs, one value (`house_base.WIN`). The cottage front windows are 3 x 3.
- Clear plaster from window or door surround to other wood or the roof: `MARGIN` 1.35 studs. My first rule was 1.5; I lowered it to fit bigger windows and told the user. **[My conclusion]** Size the floors from the windows outwards.
- Door 3.5 x 6.5 studs. Corner posts 0.8 x 0.7, floor beam 0.74, one size per house (`house_base.py`).

### Paint and build methods
- **Colour looks as layers:** finished sheets stay untouched; `house_looks.py` regrades per material using rects in `kit.json`. **[My conclusion]** This let the user compare looks without risk, and it let the Studio grade sit on top of the approved look.
- **One wood gradient per house:** each timber is painted from its world height (rich at the top), with only a faint fall per face. Timbers share paint only with others at the same height, which costs density (38.5 to 35 on the townhouse frame).
- **Stacked washes:** overlapping layers agree at the top and separate only near the lower edge. No gaps, so no accidental highlights.
- **Green wood:** rich cold teal at the top per door or shutter, breaking into fingers along the grain.
- **Plan the highlights:** `plan()` in `cottage_kit.py` places a run on chosen beams only. Windows' reflections are soft cloud shapes, some nearly none.
- **Stone reuse:** `tools/art/house_stone.py` loads `bridge_kit.py` by exec, with its own colours. Wall stones stop at the arch, ledges carry it, corner blocks cover ends. Moss painted on stone cards (`stone_extras.paint_moss`).
- **Post joints:** `add_joints()`: collar under the beam, shoe at the foot, one painted peg.
- **Shared kit:** `cottage_kit.py` is the library, `house_base.py` holds approved values and `block()`, then one `*_kit.py` per house.
- **Studio pipeline:** `tools/blender/houses_export.py` -> `tools/art/houses_upload.py` (skips unchanged, keeps old ids) -> `tools/art/houses_luau.py` -> `tools/studio/place_houses.luau` for a first build, `tools/studio/recolour_houses.luau` for colour changes.
- **Test before uploading all:** `houses_upload.py <look> House,House`. Two houses cost 15 uploads to settle a grade that then took 49 more.

## 4. Technical traps

| Trap | Fix |
|---|---|
| The Roblox glb import turns each mesh 180° about its own centre, which also slides parts apart | `CFrame.new(centre) * CFrame.Angles(0, math.pi, 0)` per part |
| Studio captures come back blank | The user brought Studio to the front. Later, the first captures of a run still came back blank, and retaking them worked. Pass `camera_position` and `look_at_position` |
| Studio's upload folder isn't approved, and it's a security setting I may not change | Used the user's own `upload_asset.py` and Open Cloud key, disclosed to them. Never computer-use on their PC |
| Rerunning a placement script would wipe hand-placed work | Colour swaps go through `recolour_houses.luau`; it updated the user's `Workspace.Bridgehouse` copy too, moving nothing |
| Plum shadows went vivid purple and stone went blue in Studio shade | Softened the shadow colour, then the user's "colder" darks replaced plum on plaster |
| Lit sides matched Blender closely while shaded sides read darker and bluer | Judge both sides in Studio; a Blender render can't show this |
| Phantom painted shadows from a removed sill rail looked like an error | Removed. Saved as a memory: paint a shadow only where something casts it |
| Posts sticking past beams, varying thicknesses, random taper, corner stones in a different tone, plaster stroke ghosts | These caused the "not uniform" look. One post size, stop at beam, lower `BEAM_TAPER`, fainter strokes (`house_base.setup`) |
| Gradient started by the face rounded flat boards into logs | Start it lower. Same trap hit the props |
| Stone sheet full with brick variants | Don't store old stone colours in variants |
| A leftover `*_Walls_Normal.png` stayed on disk after stone moved off the Walls sheet | Deleted it, since renders load a normal map if the file exists |
| `Lighting.Technology` can't be read from the Luau tool | Leave it out |
| Roblox assets are permanent through this route; they can only be removed from the Creator Dashboard | Upload only what changed. The kit has made 125 assets (64 of them have since been replaced), on top of 8 from the first test cottage |
| Tool calls with heredocs and quoting failed in bash | Write a small script file and run that |

## 5. Scope

Rules the user stated:
- [Only houses, likely wider] Few, planned highlights; never a random rhythm on every edge. **[My conclusion]** They said this about the cottage and it may apply to all built structures. Fence and props are unconfirmed.
- [All assets] Too much visual noise is the main failure; leave negative space.
- [Only houses] Generous plaster around windows, the door, and all wood. Separate wood parts don't touch.
- [Only houses] Windows square and one size.
- [Unsure] Reference isn't law for structure ("make it good ur own way"). Said about this cottage and the townhouse concept; may be general.
- [Unsure] Gradients are collective across the object, not per piece, with the rich dark at the top. Said for wood on houses. Could apply to any assembled asset.
- [Only houses] Plaster keeps its cream; darks and streaks are colder; no streak highlights; one wash per white block.
- [Unsure] "Darkenings to be colder" is about plaster. It may or may not apply elsewhere; the wood's darks stayed warm and they approved them.
- [All assets, but verify] No yellow or orange stains. Said about plaster only, so this may be too broad.
- [All assets] Paint moss on stone rather than model clumps. Said about house bases. **[My conclusion]** that it applies to all.
- [Only houses] Dark warm stone frames a house.
- [Only houses] Stone connects: arches built into walls, connecting pieces at corners.
- [Unsure] Stay away from point lights. Said about the houses; it may be a lighting-wide preference.
- [All assets] Triangle counts weren't a concern up to about 19,000 on a large prop. Said "The try count will be fine" about these prop houses only, so the ceiling isn't a user number.
- [Only houses] Props have no interiors. An interactive forge gets more care and VFX.

My own, not the user's:
- **[My conclusion, All assets]** Colour look layers keep the approved design separate from a per-lighting grade.
- **[My conclusion, All assets]** Test a grade on a few assets before uploading all.
- **[My conclusion, All assets]** Tint plaster-like light paint in proportion to lightness, so dark details keep their colour.
- **[My conclusion, Only houses]** Face doors towards the sun where possible.
